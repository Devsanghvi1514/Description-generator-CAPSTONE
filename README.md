# Image Description Generator Using Deep Learning

Full-stack project with a React frontend and a FastAPI backend for image caption generation.

## Features

- Upload an image from the browser
- Preview the selected image before submission
- Generate a caption using an optional deep-learning model
- Fall back to a deterministic heuristic caption when model dependencies are unavailable
- Return image metadata and a ready-to-display result payload

## Project Structure

- `backend/` FastAPI application and caption service
- `frontend/` React + Vite UI

## Backend Setup

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## Frontend Setup

```bash
cd frontend
npm install
npm run dev
```

## Environment Variables

- `VITE_API_URL` Frontend API base URL, defaults to `http://localhost:8000`
- `ENABLE_TRANSFORMER_MODEL` Set to `1` to use the BLIP-based caption model. If `transformers` or `torch` is unavailable, the heuristic fallback remains active.
- `VISION_MODEL` Optional Hugging Face vision model name; defaults to `microsoft/Florence-2-base` for detailed local descriptions.
- `TRAINED_BLIP_MODEL` Optional local model directory created by the Flickr30k fine-tuning script. It takes precedence over `BLIP_MODEL`.

Florence-2 is configured with its detailed-caption task and a longer generation limit. The backend pins Transformers 4.49.0 because Florence's remote model code is not compatible with every newer Transformers release. The model still describes only visual content it can identify; it will not reliably infer hidden context or facts that are not visible in the image.
- `MONGODB_URI` Required MongoDB connection string, for example `mongodb://localhost:27017`
- `MONGODB_DATABASE` Optional database name; defaults to `deep_caption`

## API

- `GET /api/health` checks service status
- `POST /api/caption` accepts an uploaded image as `image` form data
- `GET /api/captions` returns the saved caption history

## Storage

- Uploaded images are stored in `backend/app/static/uploads/`
- Caption history is stored in MongoDB in the `captions` collection.

## Notes

The project uses Florence-2-base for detailed local descriptions. The first request downloads the model. If the model cannot be loaded, the heuristic fallback keeps the application available.

### Fine-tuning BLIP with Flickr30k

Flickr30k is the recommended starter dataset for this project because it provides about 31,000 real images with five human-written captions per image. It is more manageable locally than COCO while still providing varied, high-quality descriptions.

Install the training dependencies and run the opt-in training job:

```bash
cd backend
pip install -r requirements.txt
python scripts/train_blip_flickr30k.py
```

Because local training caused a system restart on the available laptop, the script now defaults to a very small CPU-only smoke run: 200 training images, 50 validation images, 100 steps, gradient checkpointing, and a frozen vision encoder. This is for testing the pipeline, not for achieving a meaningful accuracy improvement. Do not run longer training locally; use a cloud GPU or a machine with substantially more RAM/VRAM for real fine-tuning. The requirements pin `datasets==3.6.0` because the Flickr30k repository uses a dataset loading script that newer `datasets` releases no longer support. After a successful remote run, set `TRAINED_BLIP_MODEL=models/blip-flickr30k` in `backend/.env`, restart the API, and the backend will use the fine-tuned model. Do not train on captions generated by BLIP itself; human-written captions are needed to improve accuracy.
